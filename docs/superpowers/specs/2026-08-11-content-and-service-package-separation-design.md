# 内容包与服务包拆分设计

## 目标

让超级管理员清楚完成两条互不混淆的业务链路：

1. 维护学科、知识点和题目，再将内容组装成可发布的内容包。
2. 配置机构点数消耗、AI 用量上限和有效期，形成可采购的服务包。

内容包决定“能学什么”，服务包决定“可以使用多少服务”。两者不互相绑定，只在机构授权范围内分别配置。

## 信息架构

### 内容管理

左侧继续保留一个“内容管理”入口，避免增加一级菜单噪声。进入后分成两个清晰层级：

- 内容资源：包含“学科、知识点、题库”三个二级标签，表达内容生产链路。
- 内容包：作为与内容资源并列的一级页面模式，不再与学科、知识点、题库挤在同一排标签中。

使用子路径保存页面状态：`/platform/content/resources/subjects`、`/platform/content/resources/knowledge-points`、`/platform/content/resources/questions` 和 `/platform/content/packages`。默认进入“内容资源 / 学科”。刷新和浏览器前进、后退后必须恢复当前层级。内容包入口应有明确名称和数量，不使用“内容包管理”这种重复表达。

### 商品与权益

服务包仅保留以下字段：

- 名称与编码
- 类型
- 消耗机构点数
- 每日 AI 用量上限
- 有效期
- 状态
- 服务说明

删除服务包卡片、创建表单、编辑表单及领域类型中的内容包模式和内容包列表。

## 内容包交互

### 列表

列表保留搜索、学段筛选、状态和数量指标。整行可点击进入详情，行尾只保留必要的“编辑”和状态操作；删除放入更多操作并要求确认，避免高频误触。

### 详情

详情采用右侧抽屉，关闭后回到原列表筛选状态，展示：

- 基本信息：名称、编码、学段、学科、版本、状态。
- 内容范围：知识点数量、题目数量及可查看明细。
- 使用范围：已授权机构数量。
- 发布信息：当前状态和最近更新时间。

列表中的知识点数和题目数可点击并直接打开详情抽屉的对应明细分区，避免只有数字、无法追溯来源。

### 新建与编辑

采用三步流程：

1. 基本信息：名称、编码、学段和学科。
2. 选择内容：从该学科已发布的知识点和题目中选择范围，并实时显示数量。
3. 确认发布：检查配置后保存为草稿或发布。

本次演示数据为前端状态，但交互必须表现出完整闭环，不展示无法操作的虚假指标。

## 机构授权边界

机构详情继续分别配置：

- 可用内容包范围。
- 可采购服务包范围。

两组权限独立保存、独立展示。删除任何暗示“服务包自动包含内容包”的文案。

## 状态与错误处理

- 内容包状态统一为“草稿 / 已发布 / 已停用”；演示数据若暂不支持草稿，至少保留“已发布 / 已停用”。
- 已授权机构正在使用的内容包不可直接删除，只能停用。
- 内容范围为空时不可发布，并给出明确原因。
- 搜索无结果、内容为空和操作成功均使用现有后台的统一反馈样式。

## 验收标准

- 内容资源与内容包不再出现在同一排四个平级标签中。
- 用户可从内容包列表进入详情并追溯知识点、题目和授权机构。
- 新增内容包的步骤和下一步操作清晰。
- 服务包所有页面及数据类型均不再包含内容包绑定。
- 机构仍可分别配置内容包范围和服务包范围。
- 路由、刷新、返回操作符合 React Router 的页面状态逻辑。
- 类型检查、相关自动化测试和生产构建通过，并完成桌面与窄屏检查。
