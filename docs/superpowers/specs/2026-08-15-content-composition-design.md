# 内容包、知识点与题目关系改造设计

## 目标

将内容包从“按学科自动展示全部内容”的筛选页，改为总部可明确配置内容的产品单元；消除题目中重复存储的章、节与路径，使统计可由真实关系派生。

## 本轮范围

- 超级管理员为每个内容包显式选择三级知识点与题目。
- 内容包可包含多个三级知识点；也可在已选知识点中进一步选择部分题目。
- 题目只以 `knowledgePointLevel3Id` 作为知识归属；章、节、路径在展示时从知识点树计算。
- 知识点题量和内容包题量从当前有效题目与内容包选择关系实时计算。
- 机构内容包授权统一只保存内容包 ID。

本轮不包含：内容发布版本、审核流、导入任务队列、导入回滚。它们在核心关系稳定后独立实现。

## 目标关系

```text
内容包
 ├─ 内容包知识点（多个三级知识点）
 └─ 内容包题目（可选；未单独选择时使用已选知识点下全部有效题目）

题目 ── 仅绑定 ──> 三级知识点 ──> 节 ──> 章
```

内容包的“基础包 / 冲刺包 / 专项包”差异由所选知识点和题目决定，不再由学科名称隐式决定。

## 业务规则

1. 内容包至少选择一个三级知识点或一道题目才能发布；草稿可暂不完整。
2. 若内容包未配置题目白名单，则交付所选知识点下全部状态为“启用”的题目。
3. 若配置题目白名单，则只交付白名单中的启用题目；题目必须属于内容包已选的三级知识点。
4. 题目移动到其他三级知识点后，内容包归属和统计立即按新关系计算；不保留旧路径字段。
5. 已停用知识点或题目不计入可交付题量，但保留在配置中供管理员修复或替换。
6. 机构授权只保存 `contentPackageIds: string[]`；旧名称值在迁移时转换为对应 ID，不能匹配的值提示人工处理。

## 数据模型

`ContentPackageItem` 增加：

- `knowledgePointIds: string[]`：所选三级知识点。
- `questionIds?: string[]`：题目白名单；空数组或未设置表示不限制题目。

`QuestionItem` 保留 `knowledgePointLevel3Id`，移除其余两个知识点 ID 和 `knowledgePointPathName` 的写入职责。现有字段可暂时保留兼容读取，但所有新建、编辑和展示均通过知识点树派生。

`Institution.availableContentPackages` 重命名为 `availableContentPackageIds`；兼容迁移只在应用初始化执行一次。

## 界面

超级管理员在内容包编辑页按两步配置：

1. 选择三级知识点。
2. 选择题目范围：默认“该知识点全部启用题目”，或切换为“仅选定题目”。

内容包列表显示实时的知识点数与可交付题数。机构和教师端不出现新增内容包入口，只显示总部授权的内容包及其真实内容。

## 验收

1. 同学科的两个内容包可选择不同知识点或不同题目，并显示不同题量。
2. 修改题目的三级知识点后，题目在所有页面显示的新路径一致。
3. 新增、停用、移动题目后，知识点和内容包统计自动变化。
4. 内容包题目白名单不能跨越未选知识点。
5. 机构授权仅接受内容包 ID；名称值可迁移或被明确标记为待处理。
