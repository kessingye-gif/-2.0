# 学生权益、学生授权码、家长绑定码与知识点列调整设计

## 目标

让页面职责与业务对象一致：学生权益归学生管理，开通监管只负责学生授权码生成与流转，家长绑定码归家长监护关系；内容中心的知识点表按独立字段展示学科、学段和三级知识点。

本次仅调整现有桌面端演示原型的信息架构、交互文案和表格展示，不接入后端，不改变题目与三级知识点的关联方式。

## 信息架构

- 左侧主导航新增“学生管理”，复用现有 `StudentView`。
- 学生管理保留花名册、微信换绑、监护关系和诊断能力，并新增“学生权益”子页签。
- 家长绑定码的生成和记录放在“家长监护关系”子页签内，不与学生授权码混用。
- 开通监管保留 Token 订单与授权码记录，不再承担学生权益展示。
- 原“服务开通记录”统一改称“授权码记录”，避免与学生权益混用。

## 学生权益

学生权益页签以学生为主体，从现有授权码数据中派生权益记录。每条记录展示：

- 学生姓名
- 所属机构
- 责任教师
- 服务包名称
- 权益状态
- 激活时间
- 到期时间

已激活授权码显示为“已生效”；待激活授权码显示为“待激活”；已作废或已过期记录仍保留并明确标记。学生权益页面只负责查看，不提供授权码作废等流转操作。

## 授权码生成与记录

- 开通监管中的按钮文案改为“生成授权码”。
- 点击按钮后直接生成一条新的待激活授权码并插入列表首行，不打开测试表单，也不使用“测试码”相关文案。
- 演示数据继续使用当前默认机构、教师、学生和服务包，以保持原型可直接操作。
- 审计日志动作统一改为“生成学生授权码”。
- 授权码记录保留搜索、状态筛选和待激活授权码作废能力。

## 家长绑定码

- “学生管理 → 家长监护关系”增加绑定码操作区和绑定码记录。
- 点击“生成家长绑定码”后直接生成一条绑定码，不打开额外表单。
- 演示生成使用当前首位可用学生及其所属机构作为绑定目标，生成结果插入记录首行。
- 记录展示绑定码、目标学生、所属机构、生成时间、到期时间和状态。
- 状态分为“待绑定”“已绑定”“已失效”；现有有效监护关系映射为已绑定演示记录，新生成记录默认为待绑定。
- 家长绑定码仅用于建立家长与学生的监护关系，不开通学生服务，不消耗服务额度。
- 本次原型只提供直接生成和状态查看，不增加人工改绑、撤销或重新发送流程。

## 知识点表格

知识点平铺表格改为以下独立列：

1. 学科
2. 学段
3. 一级知识点
4. 二级知识点
5. 三级知识点
6. 教材版本
7. 关联精选题
8. 快捷操作

学段从知识点的年级信息归一化得到，沿用项目现有教育阶段工具；教材版本直接使用知识点记录中的版本字段。三级知识点缺失时继续显示现有缺省提示。

## 数据流与边界

- `App` 继续持有学生和学生授权码状态，并把授权码传给学生管理与开通监管。
- 家长绑定码作为学生管理内部的演示状态维护，不与学生授权码共用类型或状态字段。
- 学生权益由授权码状态实时派生，不新增重复状态源。
- 生成或作废授权码后，授权码记录与学生权益同步更新。
- 生成家长绑定码后，家长监护关系中的绑定码记录立即更新；不影响学生权益。
- 不修改 `KnowledgePointNode` 数据结构，不改批量导入格式，不改题目外键。

## 异常与空状态

- 学生权益无记录时显示明确空状态。
- 授权码筛选无结果时保留现有空列表表现。
- 家长绑定码无记录时显示明确空状态。
- 已激活授权码不可作废的现有约束保持不变。
- 表格宽度不足时使用横向滚动，不压缩到不可读。

## 验收标准

1. 左侧可进入“学生管理”，并能打开“学生权益”页签。
2. 开通监管不再以“服务开通记录”或“学生权益”命名授权码列表。
3. 点击“生成授权码”后立即出现一条待激活记录，界面和审计中均无“测试码”字样。
4. 新生成或作废授权码后，学生权益页中的对应状态同步变化。
5. 家长监护关系中可点击“生成家长绑定码”并立即看到一条“待绑定”记录。
6. 家长绑定码记录明确展示目标学生、机构、生成时间、到期时间和状态，且不混入学生授权码列表。
7. 知识点表分别展示学科、学段、一级知识点、二级知识点、三级知识点和教材版本。
8. TypeScript 检查、单元测试和生产构建通过。
9. 桌面浏览器中学生管理、学生授权码记录、家长绑定码记录和知识点表无主要内容遮挡。

## 验证

- 运行现有测试、类型检查和生产构建。
- 在浏览器中检查学生管理入口与权益页签。
- 点击生成授权码并确认列表立即更新。
- 在家长监护关系中点击生成家长绑定码并确认记录立即更新。
- 切换到知识点表，检查所有拆分列及横向滚动。
