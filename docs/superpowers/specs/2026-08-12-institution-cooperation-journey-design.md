# 机构合作方案与跨模块交互重设计

## 1. 执行摘要

第三轮采用“机构合作方案”作为超级管理员业务主线的配置中心。内容包和服务包不再由机构详情中的两组长复选框逐项配置，而是组合为一套可复用、可追溯的合作方案；机构创建时选择方案，特殊机构再做差异调整。

本轮目标不是增加后台功能数量，而是保证同一业务对象只有一个数据来源和主要维护入口，让用户能够连续完成：

`创建合作方案 → 新增机构 → 额度入账 → 导入老师与学生 → 办理学生服务 → 查看服务权益`

## 2. 已知事实与约束

### 已知事实

- 当前原型主要面向客户演示，首要目标是直观、易学和流程连贯。
- 第三轮只完善超级管理员操作主链，机构管理员视角暂不展开。
- 机构不能默认获得全部内容包或服务包，所有可用范围必须经过明确授权。
- 内容包与服务包必须统一组成“机构合作方案”，但在方案内仍分为“教学内容”和“服务权益”两部分展示。
- 新增内容包或服务包不会自动授权给已有机构。
- 学科、学段、年级和教材版本继续由系统基础数据统一维护。
- 学生授权码、家长绑定码和服务权益只能由一次学生服务办理产生。

### 本轮不包含

- 后端、数据库、真实支付、真实消息通知和完整 RBAC。
- 机构管理员端完整工作台。
- 合同电子签署、发票和真实财务对账。
- 合作方案的复杂审批流。

## 3. 角色与核心业务流程

### 角色

- 超级管理员：维护合作方案，创建机构，配置机构授权，录入额度，组织老师、班级和学生，办理学生服务并处理异常。
- 机构：合作方案和业务数据的归属主体，本轮不作为直接操作角色展开。

### 主流程

1. 超级管理员在“商品与权益”创建机构合作方案。
2. 在方案中分别选择教学内容、可采购服务包，并填写建议初始额度和合作期限。
3. 新增机构时选择合作方案，系统自动带出授权明细。
4. 管理员可在确认步骤做本机构的特殊调整，但不能改变合作方案模板。
5. 创建完成后进入机构工作台，按待办顺序完成额度入账、老师、班级和学生准备。
6. 从学生花名册发起服务办理，生成学生授权码、家长绑定码和服务权益。
7. 回到学生管理查看办理结果，从机构工作台查看整体履约进度和异常。

### 例外流程

- 方案停用：已有机构继续保留授权，新机构不能选择该方案。
- 方案修改：必须选择“仅用于新机构”或“同步到已使用机构”；同步前展示影响机构数量和差异。
- 机构特殊调整：记录为机构覆盖项，不回写合作方案。
- 商品停用：不能新增到合作方案；已有授权保留历史快照，但不能继续办理。
- 机构额度不足：学生办理被阻止，并提供直达该机构额度入账的操作。
- 重复办理：同一学生存在待激活或有效权益时提示风险，不能静默重复生成。

## 4. 模块归属与边界

### 系统管理

- 拥有：学段、年级、学科、教材版本、知识类型等基础数据。
- 不拥有：内容包、服务包、合作方案和机构授权。

### 内容管理

- 拥有：章、节、知识点、精选题库、内容包。
- 输出：已发布且可授权的内容包目录。
- 不拥有：机构授权关系和服务权益。

### 商品与权益

- 拥有：服务包、AI 加油包、机构合作方案、额度入账和商业流水。
- 合作方案引用已发布内容包和可用服务包，不复制其定义。
- 不拥有：老师、班级和学生档案。

### 机构管理

- 拥有：机构资料、选用方案、机构特殊调整、机构管理员账号和机构履约概览。
- 展示实际授权范围，但不创建内容包或服务包。

### 老师、班级与学生管理

- 拥有：各自业务档案和组织关系。
- 必须有明确机构归属。
- 学生管理展示服务办理结果，不独立生成双码。

## 5. 核心数据与业务规则

### CooperationPlan（机构合作方案）

- 标识、名称、编码、状态。
- 适用学段、年级、学科说明。
- 内容包 ID 列表。
- 服务包 ID 列表。
- 建议初始额度。
- 建议合作期限。
- 版本号、创建时间、更新时间。

规则：方案必须至少包含一个内容包和一个服务包才能启用；停用方案不可供新机构选择。

### InstitutionAgreement（机构合作配置）

- 机构 ID。
- 合作方案 ID 和版本快照。
- 生效日期、到期日期、状态。
- 实际内容包 ID 列表。
- 实际服务包 ID 列表。
- 特殊调整说明。

规则：机构实际范围来源于方案快照加机构覆盖项。调整机构配置不会修改原方案。

### 关键状态

- 合作方案：草稿 → 已启用 → 已停用。
- 机构合作配置：待确认 → 已生效 → 已到期 / 已终止。
- 机构履约阶段：资料已建 → 方案已授权 → 额度已入账 → 组织已建立 → 学生已导入 → 可办理服务。

## 6. 信息架构和页面设计

### 商品与权益：新增“机构合作方案”页签

列表展示方案名称、教学内容范围、服务包范围、使用机构数、状态和更新时间。

主要操作是“新建合作方案”。编辑页分为：

1. 基本信息。
2. 教学内容：按学段、学科筛选后选择已发布内容包。
3. 服务权益：选择可采购服务包并展示点数、AI 用量和服务期。
4. 商务建议：初始额度和合作期限。
5. 确认与启用：展示完整摘要和校验错误。

### 新增机构：四步向导

1. 基本信息。
2. 选择合作方案。
3. 确认授权范围，可添加本机构特殊调整。
4. 创建管理员账号并确认创建。

完成后进入机构工作台，不返回无上下文的机构列表。

### 机构工作台

用独立页面替代信息过载的侧边抽屉：

- 概览：合作状态、额度、老师、班级、学生和履约进度。
- 合作方案：方案版本、实际授权范围和特殊调整。
- 组织成员：带机构上下文跳转老师、班级和学生。
- 额度与流水：直达已预选机构的入账单和流水。
- 操作记录：授权、额度和组织变更记录。

页面首屏只突出一个“下一步”主操作，依据履约阶段变化。

### 跨模块跳转规则

- 机构工作台 → 老师、班级、学生：自动设置机构筛选。
- 机构工作台 → 额度入账：自动预选机构并打开表单。
- 学生花名册 → 办理服务：自动带入机构、老师和学生。
- 内容包 / 服务包详情 → 授权机构：自动筛选引用该对象的合作方案和机构。
- 返回时保留筛选、滚动位置和当前详情对象。

## 7. 交互状态与防错

- 方案未选择时不能进入授权确认步骤。
- 方案引用停用商品时显示阻断错误和修复入口。
- 保存机构特殊调整前展示相对方案的新增和移除项。
- 同步修改已有机构前展示影响数量，不默认勾选同步。
- 所有成功页面给出明确下一步，不使用阻塞式浏览器弹窗。
- 额度不足、重复办理、缺少教师或机构时保留输入并给出可执行修复动作。
- 列表返回时保留筛选条件。

## 8. 权限与审计

- 只有超级管理员可创建、启停和修改合作方案。
- 机构授权调整、方案同步、额度入账和服务办理必须记录操作人、时间、对象、变更前后差异和原因。
- 停用、终止、同步已有机构属于高影响操作，需要二次确认和影响范围预览。
- 原型阶段使用前端共享状态模拟，接口和持久化留待正式开发阶段。

## 9. 第三轮交付切片

### 切片一：合作方案主数据

- 合作方案列表、创建和编辑。
- 引用正式内容包目录和服务包目录。
- 启用校验和状态展示。

### 切片二：机构创建与工作台

- 四步机构向导。
- 机构工作台与履约进度。
- 机构特殊调整和实际授权摘要。

### 切片三：跨模块上下文

- 机构到额度、老师、班级、学生的预筛选跳转。
- 商品到授权机构的反向查看。
- 返回状态保留。

### 切片四：完整演示验证

- 从合作方案创建到学生服务权益查看的端到端演示。
- 空状态、停用商品、额度不足和重复办理验证。
- 自动化测试、类型检查、构建和浏览器检查。

## 10. 验收标准

1. 创建机构时必须选择已启用合作方案，不能默认拥有全部商品。
2. 选择方案后自动带出内容包和服务包，无需从两组长列表重新逐项勾选。
3. 特殊调整与方案模板清晰区分，保存后可追溯差异。
4. 新增商品不会自动授权给已有机构。
5. 机构创建完成后可按页面提示连续完成额度、组织和学生准备。
6. 所有跨模块跳转自动携带机构或学生上下文。
7. 同一数据只在其归属模块维护，其他模块只引用或展示。
8. 学生办理成功后双码和服务权益来自同一次办理结果。
9. 整条主线无无效按钮、重复生成入口和阻塞式成功弹窗。

## 11. 主要风险与决策记录

- 决策：内容包和服务包组成统一合作方案。原因是减少机构重复配置，同时保留教学内容与服务权益的业务差异。
- 决策：明确授权而非默认全部可用。原因是机构合同范围不同，新商品不能自动扩权。
- 决策：方案采用版本快照与机构覆盖项。原因是防止修改模板时静默改变已有机构权益。
- 风险：当前内容包仍由内容页面本地状态维护。第三轮需先抽为根级共享目录，否则合作方案无法稳定引用。
- 风险：现有机构详情文件职责过多。实施时只拆分合作方案和工作台相关组件，不做无关重构。
