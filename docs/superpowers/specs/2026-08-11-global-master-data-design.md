# 全局基础数据与公共组件设计

## 目标

将学段、年级、学科、教材版本和知识类型从各页面的硬编码与局部状态中抽离，建立全局可维护的基础数据源。系统设置负责维护，业务页面通过公共函数和公共选择组件实时调用同一份数据。

本期使用前端内存状态，刷新后恢复演示初始值；接口形状应支持未来替换为后端 API。

## 数据模型

所有基础数据包含 `id`、`code`、`name`、`status`、`sortOrder`。其中：

- 学段 `EducationStage`：小学、初中、高中等。
- 年级 `GradeMaster`：必须关联一个 `stageId`。
- 学科 `SubjectMaster`：可关联一个或多个 `stageIds`。
- 教材版本 `TextbookVersion`：可限定适用的 `stageIds`，空数组表示全学段。
- 知识类型 `KnowledgeTypeMaster`：保留适用学科、启停状态和使用数量。

业务记录继续保存当时的名称快照。基础数据改名不会改写历史学生、题目、知识点或订单记录；新建和编辑业务数据时使用最新基础数据。

## 全局状态

新建 `MasterDataProvider` 与 `useMasterData()`：

- Provider 在应用根部挂载，是五类基础数据的唯一可变状态源。
- 使用 reducer 实现新增、编辑、启用和停用。
- 提供按状态和关联关系查询的 selector，页面不自行拼装筛选逻辑。
- 预留 `load`/`replaceAll` 边界，未来可将初始值替换为接口返回值。
- 当前阶段不写 localStorage，不新增第三方状态库。

## 公共函数

公共函数负责：

- 获取启用的学段、年级、学科和教材版本。
- 按学段筛选年级。
- 按学段筛选学科与教材版本。
- 统一按 `sortOrder` 和名称排序。
- 校验编码与名称在同一类型内不重复。
- 判断数据是否已被业务记录引用；已引用数据禁止删除，本期统一使用停用。

## 公共组件

建立四个领域选择组件：

- `StageSelect`
- `GradeSelect`
- `SubjectSelect`
- `TextbookSelect`

组件统一接收 `value`、`onChange`、可选 `stageId`、空选项文案和禁用状态。默认只展示已启用数据；业务表单不再手写基础数据 `<option>`。

同时抽取通用的基础数据管理表格与编辑弹窗，系统设置复用同一套新增、编辑和启停交互。

## 系统设置

“基础数据”页改为五个真实子模块：学段、年级、学科、教材版本、知识类型。

- 每个模块展示名称、编码、关联范围、排序和状态。
- 支持新增、编辑、启用和停用。
- 年级编辑必须选择学段。
- 学科可选择多个适用学段。
- 教材版本可选择多个适用学段。
- 重复编码或名称在保存前阻止并显示原因。
- 已被业务使用的数据只允许停用，不直接删除。

## 业务页面迁移

第一期迁移以下入口：

- 内容管理：学科管理、内容包筛选和内容包创建。
- 知识点与题目：筛选、单条录入和批量导入预览相关选项。
- 教师与班级：年级和学科选择。
- 学生管理：年级筛选改用启用的年级顺序，并继续从学生共享数据中计算实际可选范围。

迁移时保持现有业务对象和交互不变，仅替换基础选项来源。无法映射到基础数据 ID 的历史名称仍可展示，但不能作为新建数据的默认选项。

## 异常与空状态

- 某类基础数据全部停用时，选择器显示“暂无可用数据”并禁用。
- 上级学段变化后，下级年级、学科或教材版本值若失效，组件通知业务表单清空。
- 删除操作本期不提供，避免破坏历史引用。
- Provider 外调用 Hook 时抛出明确开发错误。

## 测试

- reducer：新增、编辑、启停和重复校验。
- selector：学段与年级、学科、教材版本联动。
- 公共选择组件：启用项展示、空状态和上级变化清空。
- 系统设置：基础数据可维护且修改后其他页面读取新值。
- 完整 TypeScript 检查、现有测试和生产构建。

## 验收标准

1. 系统设置修改基础数据后，业务页面无需刷新即可读取变化。
2. 学段、年级、学科、教材版本不再由迁移页面手写固定选项。
3. 年级、学科和教材版本能按学段正确联动。
4. 停用项不会出现在新建业务表单中，但历史记录仍正常展示。
5. 重复编码或名称无法保存。
6. 全局状态、公共函数和公共组件均有自动化测试。
7. 不新增第三方状态库，不提交本次工作区改动。
