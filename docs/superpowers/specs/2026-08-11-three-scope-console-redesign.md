# 平台、机构与老师三层管理端重构设计

## 1. 目标

将当前混合平台运营、机构管理和老师执行职责的单一后台，重构为权限边界清晰、数据可追溯、路由可下钻的三层产品。本阶段优先完成平台总部端，同时为后续机构端和老师端预留可复用的业务模型与组件边界。

本产品不包含合同、签约、回款审批等 CRM 或销售管理流程。平台与机构的核心商业关系是“机构额度分配与服务使用”。

## 2. 三层产品边界

### 2.1 平台总部端

平台管理机构级资源和全局规则：

- 创建、停用和查看机构。
- 向机构分配、追加或冲减总额度。
- 为机构配置可使用的平台内容包与服务包。
- 维护平台学科、平台内容包、平台题库和平台知识点。
- 查看全平台的机构、学生、激活、学习使用和额度消耗汇总。
- 处理跨机构异常、补发、退款和审计。

超级管理员拥有机构管理员和老师的全部业务能力，可在指定机构范围内批量导入老师、分配老师额度、管理班级和学生、查看学习情况并进行纠错。这些能力放在机构详情下，不扩张平台一级菜单。总部代操作必须记录真实操作人、作用机构、操作能力和原因。

### 2.2 机构端

机构账号只能操作本机构数据：

- 查看平台分配给本机构的总额度、已分配额度和剩余额度。
- 管理本机构老师，并向老师分配额度。
- 管理本机构班级和学生。
- 维护本机构私有题库和私有知识点。
- 只读使用平台分配给本机构的内容包、题目和知识点。
- 查看本机构学生开通、激活、学习和服务使用情况。

机构端内容中心不提供学科管理和内容包管理。

### 2.3 老师端

老师在机构授权范围内执行教学：

- 查看个人获分配额度及使用情况。
- 管理自己负责的班级和学生。
- 为学生选择可用服务并执行开通。
- 使用机构授权的平台内容和本机构内容。
- 在权限允许时维护个人题目。
- 查看自己负责学生的学习情况。

## 3. 核心业务链路

平台与机构共同构成的主链路为：

```text
平台创建机构
→ 平台给机构分配总额度
→ 平台配置机构可用内容包与服务包
→ 机构创建老师并分配老师额度
→ 老师管理班级与学生
→ 老师为学生开通服务
→ 学生激活并使用内容与 AI 服务
→ 产生学习数据和额度消耗
→ 续充、补发、退款或异常处理
```

每个可见数字都必须能回答“口径是什么、数据从哪来、关联对象是谁、点击后去哪”。

## 4. 平台驾驶舱

首页不再使用“签约漏斗”、“合同”、“回款”等概念，改为四个明确的监管区域。

### 4.1 机构与额度

- 机构总数、正常机构、待配置机构。
- 已分配机构额度、机构剩余额度、低额度机构。
- 点击指标进入机构列表或额度流水，并保留对应筛选条件。

### 4.2 学生与开通

- 学生总数、本期新增学生、已开通学生、待激活学生。
- 激活率、长期未激活、服务即将到期。
- 可按机构、老师、班级、学生和开通状态下钻。

### 4.3 学习与使用

- 活跃学生、今日或本周学习人数。
- 练习完成量、诊断报告数、AI 调用量和 Token 消耗。
- 机构活跃率对比、学科使用分布和长期未学习学生。
- 平台只进行监管与异常下钻，不在首页执行班级或学生日常管理。

### 4.4 待办与异常

- 机构未分配额度。
- 机构未配置内容或服务范围。
- 机构额度低于预警值。
- 学生开通后长期未激活或激活后无学习记录。
- Token 消耗异常、付费未到账、退款或补发待处理。

异常项必须进入对应的可处理记录，不得只切换到模块首页。

## 5. 内容中心边界

### 5.1 平台内容中心

- 学科管理。
- 内容包管理。
- 平台题库。
- 平台知识点。
- 向机构配置可用内容范围。

### 5.2 机构内容中心

- 我的题库：本机构私有。
- 我的知识点：本机构私有。
- 平台内容：只读查看平台已分配的内容。

机构内容中心不出现学科管理和内容包管理，不允许修改平台内容。

## 6. 路由与下钻规范

不再使用根组件的 `currentTab` 和业务组件的 `mode` 作为主导航机制。本阶段引入声明式路由，保证刷新恢复、前进后退、可复制链接和精确下钻。

平台端目标路由：

```text
/platform/dashboard
/platform/institutions
/platform/institutions/:institutionId
/platform/institutions/:institutionId/quota
/platform/institutions/:institutionId/scope
/platform/content/subjects
/platform/content/packages
/platform/content/questions
/platform/content/knowledge-points
/platform/activations
/platform/learning
/platform/after-sales
/platform/audit
/platform/settings
```

筛选、排序和页码写入 URL 查询参数。驾驶舱指标、全局搜索结果和表格关联字段必须链接到精确列表或详情路由。

## 7. React 组件规范

### 7.1 边界

- `App` 只负责应用入口、身份上下文、路由和顶层反馈。
- 业务页面使用明确名称，不使用 `mode` 在一个组件中切换多个独立业务。
- 页面只组合业务区块；业务状态和交互放入对应 feature；通用表格、筛选、弹窗、状态标签放入通用组件。
- 平台端、机构端和老师端共享领域类型、权限函数和基础组件，不共享页面权限假设。

### 7.2 状态

- URL 保存导航、筛选、排序、页码和当前详情 ID。
- 服务端数据使用页面或 feature 数据层管理。
- 表单状态保留在表单或对应 feature 内。
- 全局状态仅保存当前用户、机构上下文、权限和全局消息。

### 7.3 操作闭环

所有写操作必须包含：

```text
输入校验 → 影响确认 → 提交中 → 成功或失败反馈 → 数据刷新 → 审计记录
```

页面不得出现无处理函数的主操作按钮、无筛选行为的搜索框、无数据行为的分页器或固定成功数量的模拟导入提示。

## 8. 权限与数据归属

题目、知识点、班级、学生、额度流水和开通记录必须具有明确的机构归属。内容资源额外记录所有者类型。

```ts
type OwnerType = 'platform' | 'institution' | 'teacher';

interface ResourceOwnership {
  ownerType: OwnerType;
  ownerId: string;
  institutionId?: string;
  teacherId?: string;
  createdBy: string;
}
```

权限判断统一基于“能力 + 当前机构范围 + 资源所有者 + 操作”，不得仅通过隐藏菜单实现权限。权限继承关系为“超级管理员能力 ⊇ 机构管理员能力 ⊇ 老师能力”，每次操作仍必须带明确的机构或老师数据范围。

## 9. 交互与后台界面规范

- 主导航和可下钻数据使用语义化链接。
- 可点击元素使用 `button` 或链接，不使用带 `onClick` 的 `span`/`div`。
- 弹窗和抽屉具有对话框语义、标题关联、焦点限定、Esc 关闭和焦点恢复。
- 危险操作要求二次确认、影响说明、操作原因和审计记录。
- 表格统一支持加载、空数据、错误、筛选、真分页和详情入口。
- 图标按钮具有可访问名称，表单标签和输入正确关联，所有键盘操作都有可见焦点。
- 日期、金额和 Token 数量通过统一格式化函数输出。

## 10. 第一阶段验收标准

1. 平台菜单不再出现“客户与合同”等非需求概念。
2. 平台驾驶舱同时展示机构与额度、学生与开通、学习与使用、待办与异常。
3. 驾驶舱指标有数据口径、更新时间和精确下钻去向。
4. 平台内容中心保留学科、内容包、平台题库和平台知识点，页面文案明确这些是平台资产。
5. 所有一级导航、仪表指标和搜索结果使用可恢复路由，不再依赖 `currentTab` 条件渲染。
6. 平台一级菜单不单独展开老师、班级和学生管理；超级管理员从机构详情进入后，可使用机构和老师的全部管理能力。
7. 至少完成驾驶舱下钻、URL 状态恢复、权限边界和关键操作闭环的自动化测试。

## 11. 实施顺序

1. 建立平台路由和菜单边界，移除合同/签约概念。
2. 重做平台驾驶舱及四类下钻。
3. 重做机构详情的额度、服务范围、学生/学习汇总和审计关联。
4. 拆分平台内容中心的学科、内容包、题库和知识点页面。
5. 拆分当前 `GoodsView` 和 `SystemView` 的模式开关。
6. 补齐搜索、分页、异常、退款、补发与审计闭环。
7. 固化共享领域类型和权限函数，作为后续机构端和老师端的基础。
