# 商业履约演示版改版设计

## 目标

将当前“功能页面集合”重组为老板首次打开即可理解的商业履约演示后台。主线是：机构签约、额度到账、服务配置、授权码生成、学生激活、服务履约、续费或退款。

本阶段为桌面端可交互演示原型，使用模拟数据，不接入真实后端。刷新页面后允许恢复初始演示数据。

## 信息架构

左侧主导航重组为：

1. 经营驾驶舱
2. 客户与合同
3. 商品与定价
4. 开通与履约
5. 订单与资金
6. 售后与异常
7. 数据与审计
8. 平台设置

教师、班级、学生和诊断能力不作为本次主导航的独立主线；仅在学生开通和履约需要时作为上下文信息展示。

## 经营驾驶舱

首屏依次展示：

- 本月签约金额
- 本月额度到账
- 本月开通学生
- 本月履约收入
- 本月退款金额

核心区域展示七段履约漏斗：

` 机构签约 → 额度到账 → 服务配置 → 授权码生成 → 学生激活 → 服务履约 → 续费/退款 `

每个节点显示数量、转化率或金额，并能跳转到相应业务列表。

下方展示：

- 今日待办：额度不足、授权码将过期、支付未到账、激活异常、退款待审。
- 机构履约健康度：展示正常、预警和异常机构。
- 最近履约动态：以时间线展示关键业务动作。

## 业务中心

### 客户与合同

复用机构管理能力，将机构列表重心改为签约与履约状态。机构详情新增履约进度条，并展示合同金额、已购额度、已分配额度、已激活学生、累计消耗、关联订单和异常记录。

### 商品与定价

集中展示服务包和 Token 加油包。保留新增、编辑、上下架与定价信息，突出对应履约内容、有效期和额度消耗。

### 开通与履约

统一展示授权码生成、发放、激活、过期和作废状态。列表必须同时显示机构、学生、服务包、生成时间、激活时间和当前履约状态。

### 订单与资金

整合机构充值、服务包兑换、Token 加油包购买与退款交易。页面给出支付金额、额度变化、订单状态和关联机构。

### 售后与异常

将异常处理统一成待办工作台，包含额度补发、额度扣回、授权码作废、支付异常和退款审核。处理后必须更新当前状态并生成履约动态或审计日志。

### 数据与审计

保留现有审计列表，统一记录关键演示操作。无需在本阶段增加复杂报表中心。

## 交互与数据流

- 主导航和驾驶舱节点共享同一套页面状态。
- 仪表盘统计从当前模拟业务数据派生，避免同一指标在不同页面不一致。
- 演示操作至少同步更新业务对象状态、相关统计和最近动态。
- 全局搜索仅搜索机构、学生、授权码和订单。搜索结果提供对应业务页跳转。
- 成功反馈使用页面内状态或轻量通知，避免依赖阻塞式弹窗来表达履约结果。

## 异常与空状态

- 漏斗节点无数据时显示零值和简短说明，不隐藏节点。
- 列表无结果时显示当前筛选条件和清除入口。
- 不允许的操作显示业务原因，例如已激活授权码不可作废。
- 退款、额度扣回等高风险操作需要二次确认，并显示影响。

## 验收标准

1. 首次打开后，用户不进入二级页面也能说明平台的七段履约流程。
2. 从驾驶舱任一漏斗节点可一次点击到对应业务列表。
3. 可演示一条完整路径：查看机构、配置服务、生成授权码、激活学生、查看订单、处理异常、查看审计。
4. 处理一项待办后，待办状态、驾驶舱指标和最近动态保持一致。
5. 所有主导航项都有可访问内容，不出现无反应的主操作按钮。
6. 当前桌面演示分辨率下不出现主要内容被遮挡或横向溢出。

## 验证

- 运行现有 TypeScript 检查和构建。
- 为导航映射、漏斗跳转和关键状态派生逻辑增加测试。
- 在实际浏览器中走查完整演示路径，核对主界面、交互反馈和数据一致性。
